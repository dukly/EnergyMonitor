# Установка агента EnergyMonitor

## Linux (шлюз / Raspberry Pi)

Скрипты: [`install/gateway/`](../install/gateway/)

| Шаг | Действие |
|-----|----------|
| 1 | Скопировать репозиторий на устройство |
| 2 | RS485 → USR-W610 → LAN, прописать `MODBUS_HOST` в `.env` |
| 3 | `sudo bash install/gateway/install.sh` |
| 4 | Отредактировать `/opt/energy-monitor-agent/.env` |
| 5 | `sudo systemctl enable --now energy-monitor-agent` |

Нужен Python 3.12. Другой каталог можно задать через
`INSTALL_DIR=/srv/energy-monitor bash install/gateway/install.sh`;
systemd unit генерируется с фактическими путями. `.env` читает само приложение.
Повторная установка сохраняет существующий `.env` и данные.
При обновлении остановите агент, запустите установщик, затем запустите сервис:
`sudo systemctl stop energy-monitor-agent` → установка → `sudo systemctl start energy-monitor-agent`.

## Docker (отдельный способ установки)

Файлы: [`install/docker/`](../install/docker/)

| Шаг | Действие |
|-----|----------|
| 1 | Убедиться, что установлены Docker и Docker Compose Plugin |
| 2 | `bash install/docker/install.sh` (создаст `.env`, `data/`, `logs/`) |
| 3 | Отредактировать `install/docker/.env` |
| 4 | `docker compose -f install/docker/docker-compose.yml up -d --build` |
| 5 | Проверить логи: `docker compose -f install/docker/docker-compose.yml logs -f` |

## Windows

Скрипт: [`install/windows/install.ps1`](../install/windows/install.ps1)

Запустите PowerShell 5.1 или 7 **от имени администратора**, установив Python 3.12:

```powershell
.\install\windows\install.ps1
Start-ScheduledTask -TaskName EnergyMonitorAgent
```

Каталог по умолчанию — `C:\Program Files\EnergyMonitor\Agent`; пути с пробелами поддерживаются.
Новая `.env` создаётся в UTF-8 без BOM; приложение также читает старые UTF-8-файлы с BOM.
При повторном запуске установщика `.env`, `data` и `logs` сохраняются.
Параметры `-ModbusHost` и `-InverterProfile` задают только первоначальный конфиг;
для существующей установки редактируйте её `.env` явно.

Перед обновлением остановите задачу (`Stop-ScheduledTask -TaskName EnergyMonitorAgent`),
запустите установщик и затем снова запустите задачу. Код заменяется целиком,
предыдущий каталог `src` сохраняется рядом в `.src-backup-<id>` для отката.
Устаревшие файлы не остаются в активном `src`.

Задача запускается от SYSTEM при загрузке, без входа пользователя, без ограничения
длительности и с повторами после аварийного завершения (каждую минуту, до 999 попыток).
Не выбирайте каталог, доступный для записи непривилегированным пользователям.
Временная недоступность инвертора обрабатывается внутри самого агента:
он продолжает попытки подключения, включая отсутствие связи при первом запуске.

## Проверка конфигурации и БД

Интервал опроса и таймаут должны быть конечными числами больше нуля;
порт — 1–65535; Unit ID — 1–247 (пустое значение означает ID из профиля);
число повторов — 0–100; размер блока — 1–125.
Размер файла логов и число резервных логов должны быть положительными.
Ошибочная конфигурация или невозможность открыть БД приводят к ненулевому коду завершения.

В частичной таблице SQLite агент добавляет недостающие поля измерений, сохраняя
имеющиеся строки и ID. Таблицы без времени или с несовместимым `id` отклоняются;
агент не выдумывает время исторических записей и не удаляет исходные данные.
Перед обновлением рабочей БД сделайте резервную копию при остановленном агенте.

Подробный чеклист автотестов и полевого теста: [`docs/TESTING.md`](TESTING.md)

## Проверка на объекте

- [ ] USR-W610: TCP Server, порт **502**
- [ ] Ping `MODBUS_HOST` с хоста агента
- [ ] В `logs/monitor.log` появляются строки `Measurement saved`
- [ ] В SQLite есть новые строки: `SELECT * FROM measurements ORDER BY id DESC LIMIT 5;`

## Эскалация

- Modbus timeout: проверить кабель RS485, unit ID, профиль `INVERTER_PROFILE`
- Пустые значения: карта регистров не совпадает с инвертором — сменить профиль или добавить новый в `src/inverter_profiles/`

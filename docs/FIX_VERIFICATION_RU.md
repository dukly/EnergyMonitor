## Реализация

1. **Путь Windows-задачи.** Путь `src/main.py` заключён в кавычки внутри аргумента
   планировщика. Проверен реальный запуск Python с этим аргументом из каталога
   `Program Files/EnergyMonitor/Agent` во временной папке.
2. **BOM.** Новая `.env` записывается через явный UTF-8 без BOM в обеих версиях
   PowerShell. Конфигурация Python читается как `utf-8-sig`, поэтому старые файлы
   с BOM продолжают работать. Тесты читают оба варианта и проверяют пустой Unit ID.
3. **Повторная установка Windows.** Новое дерево исходников сначала копируется
   во временный каталог установки, затем заменяет активный `src`. Предыдущая
   версия сохраняется в `.src-backup-<id>`; при ошибке перемещения выполняется
   попытка вернуть прежний `src`. Обновление не создаёт `src/src` и убирает
   устаревшие файлы из активного дерева.
4. **Связь и перезапуск.** Первое подключение выполняется внутри рабочего цикла.
   Временная недоступность устройства больше не завершает процесс. Фатальная
   ошибка профиля или открытия БД возвращает ненулевой код. Windows-задача
   получает запуск от SYSTEM при загрузке, повторы аварийного завершения,
   запрет параллельных экземпляров и отсутствие лимита длительности.
5. **Настройки, БД и значения.** Оба установщика сохраняют существующий `.env`.
   Linux unit генерируется с фактическим INSTALL_DIR, конфиг читает приложение.
   В SQLite транзакционно добавляются все недостающие поля измерений; строки и
   ID сохраняются. Несовместимый ключ или отсутствие времени диагностируются
   при старте. Соединение закрывается при ошибке инициализации. Настройки имеют
   допустимые диапазоны; NaN и ±infinity не возвращаются как измеренные числа.

Для повторения локального полного прогона на Windows:

```powershell
# Необязательно: установленный переносимый busybox-w32 для shell-проверки.
$env:ENERGYMONITOR_TEST_BUSYBOX = 'C:\path\to\busybox.exe'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 src tests install/gateway/render_service.py
```

Без BusyBox на Windows одна shell-проверка пропускается. На Linux она использует
bash. Windows-тесты пропускаются на Linux. CI расширен на Ubuntu и Windows,
но удалённый прогон CI в рамках этой работы не запускался.

## Границы результата

Исправления проверены автоматическими и изолированными интеграционными тестами.
Рабочая системная задача и systemd-служба не устанавливались, перезагрузка
целевой машины не проверялась. Зависимости устанавливались в локальный `.venv`,
а не в системный Python. Реальный инвертор не подключался; его профили отложены.

Перед обновлением действующей установки следует остановить агент, сохранить
резервную копию БД, выполнить установщик и снова запустить агент. Подробности:
[INSTALL.md](INSTALL.md), [TESTING.md](TESTING.md).
